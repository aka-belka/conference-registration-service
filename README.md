# Сервис регистрации участников конференции

## Назначение

Сервис регистрации участников конференции — приложение для управления
участниками, мероприятиями и билетами. Консольная версия приложения (ПР3)
дополнена веб-интерфейсом на Django (ПР5).

Приложение позволяет:

* просматривать участников в браузере;
* просматривать информацию о конкретном участнике;
* просматривать мероприятия в браузере;
* просматривать информацию о конкретном мероприятии;
* просматривать список билетов;
* проверять доступность регистрации;
* добавлять участников (консольная версия);
* создавать мероприятия (консольная версия);
* регистрировать участника на мероприятие (консольная версия);
* отменять билет и менять его статус (консольная версия);
* хранить данные между запусками приложения.

## Используемые технологии

* Python 3;
* Django 5.2 — веб-фреймворк;
* HTML — разметка веб-страниц;
* CSS и Bootstrap 5.3 — оформление страниц;
* pytest — автоматизированные тесты;
* flake8 — проверка качества кода.

## Целевая аудитория

Организаторы конференций и мероприятий, а также администраторы,
управляющие списками участников и регистраций.

## Предметная область

Основными объектами предметной области являются:

* участник;
* мероприятие;
* билет.

Участник может зарегистрироваться на одно или несколько мероприятий
и получить билет с уникальным номером и статусом. Мероприятие имеет
ограниченное количество мест. Один участник не может иметь два активных
билета на одно и то же мероприятие. Отменённый билет не блокирует
повторную регистрацию.

## Основные сущности

### Participant — участник

Объект `Participant` представляет участника конференции.

Основные атрибуты:

* `id` — уникальный идентификатор участника;
* `name` — имя участника;
* `email` — адрес электронной почты.

Основные методы:

* `__str__()` — строковое представление участника;
* `from_data()` — создание объекта `Participant` из набора данных;
* `to_data()` — преобразование объекта в словарь для JSON.

### Event — мероприятие

Объект `Event` представляет мероприятие, доступное для регистрации.

Основные атрибуты:

* `id` — уникальный идентификатор мероприятия;
* `title` — название мероприятия;
* `date` — дата проведения;
* `max_seats` — максимальное количество мест;
* `registered` — количество зарегистрированных участников.

Основные методы:

* `has_free_seats()` — проверка наличия свободных мест;
* `is_suitable_for()` — проверка, вмещает ли мероприятие заданное число человек;
* `__str__()` — строковое представление мероприятия;
* `from_data()` — создание объекта `Event` из набора данных;
* `to_data()` — преобразование объекта в словарь для JSON.

### Ticket — билет

Объект `Ticket` представляет регистрацию участника на мероприятие.

Основные атрибуты:

* `id` — уникальный идентификатор билета;
* `event` — объект `Event`;
* `participant` — объект `Participant`;
* `status` — статус билета (`забронирован`, `оплачен`, `отменён`);
* `number` — номер билета.

Основные методы:

* `cancel()` — отмена билета;
* `change_status()` — изменение статуса билета;
* `__str__()` — строковое представление билета;
* `from_data()` — создание объекта `Ticket` из набора данных;
* `to_data()` — преобразование объекта в словарь для JSON.

## Страницы веб-интерфейса

* `/` — главная страница: описание приложения и навигация
  (view-функция `index()`);
* `/participants/` — список участников: объекты `Participant`
  из `data/participants.json` (view-функция `participants()`);
* `/participants/<int:participant_id>/` — страница участника
  (view-функция `participant_detail()`);
* `/events/` — список мероприятий: объекты `Event` из `data/events.json`
  (view-функция `events()`);
* `/events/<int:event_id>/` — страница мероприятия
  (view-функция `event_detail()`);
* `/tickets/` — список билетов: объекты `Ticket` из `data/tickets.json`
  (view-функция `tickets()`).

Если участник, мероприятие или билет с указанным идентификатором не найдены,
соответствующая страница возвращает код статуса 404.

## Обработка ошибок

Для несуществующих адресов настроена собственная страница 404.
Обработчик `handler404` объявлен в `conference/urls.py` и ссылается
на view-функцию `page_not_found()` в `homepage/views.py`.

## Основные операции

### Используется в веб-интерфейсе (ПР5)

* просмотр списка участников;
* просмотр информации об участнике;
* просмотр списка мероприятий;
* просмотр информации о мероприятии;
* просмотр списка билетов.

### Отложено до следующих работ

Эти операции реализованы в ПР3 и работают в консольной версии.
В веб-интерфейсе они появятся, когда будут добавлены формы и POST-запросы:

* добавление участника;
* поиск участника по имени;
* создание мероприятия;
* поиск мероприятия по названию;
* фильтрация мероприятий по числу мест;
* регистрация участника на мероприятие (создание билета);
* отмена билета;
* изменение статуса билета.

## Хранение данных

Данные приложения хранятся в JSON-файлах:

* `data/participants.json`;
* `data/events.json`;
* `data/tickets.json`.

При загрузке данные из JSON преобразуются в объекты `Participant`,
`Event` и `Ticket`.

При сохранении объекты преобразуются в данные JSON.

Для связи билета с мероприятием и участником в `tickets.json` используются
их идентификаторы `event_id` и `participant_id`.

## Назначение модулей

### `main.py`

Консольная версия приложения (сохранена с ПР3).
Отвечает за:

* запуск консольного приложения;
* отображение меню;
* получение данных от пользователя;
* организацию пользовательских сценариев.

### `conference/`

Пакет настроек Django-проекта:

* `settings.py` — настройки проекта;
* `urls.py` — маршрутизация верхнего уровня;
* `asgi.py`, `wsgi.py` — точки взаимодействия с сервером.

### `homepage/`

Django-приложение, отвечающее за главную страницу:

* `views.py` — функция `page()` (общий HTML-каркас) и view-функция `index()`;
* `urls.py` — маршрут главной страницы.

### `participants/`

Django-приложение, отвечающее за участников:

* `views.py` — view-функции `participants()` и `participant_detail()`;
* `urls.py` — маршруты приложения.

### `events/`

Django-приложение, отвечающее за мероприятия и билеты:

* `views.py` — view-функции `events()`, `event_detail()` и `tickets()`;
* `urls.py` — маршруты приложения.

### `models/`

Классы предметной области и функции работы с ними (пакет ПР3):

* `participants.py` — класс `Participant` и функции работы с участниками;
* `events.py` — класс `Event` и функции работы с мероприятиями;
* `tickets.py` — класс `Ticket` и функции работы с билетами.

### `storage.py`

Отвечает за загрузку и сохранение данных.
Выполняет преобразование:

* JSON → объекты Python;
* объекты Python → JSON.

### `utils.py`

Содержит вспомогательные функции консольного ввода:

* `input_int()` — безопасный ввод целого числа;
* `input_date()` — безопасный ввод даты;
* `input_non_empty()` — безопасный ввод непустой строки;
* `input_email()` — безопасный ввод email.

### `tests/`

Содержит автоматизированные тесты проекта.

## Запуск приложения

Веб-версия (Django):

```bash
python manage.py runserver
```

