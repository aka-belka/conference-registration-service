# Сервис регистрации участников конференции

## Назначение

Консольное приложение для управления регистрацией участников на конференции. Позволяет вести список участников и мероприятий, регистрировать участников на мероприятия (создавать билеты), отменять регистрацию и менять статус билета.

## Целевая аудитория

Организаторы конференций и мероприятий, а также администраторы, управляющие списками участников и регистраций.

## Предметная область

Управление регистрацией на конференции. Основные объекты предметной области: участник, мероприятие, билет. Участник может зарегистрироваться на одно или несколько мероприятий и получить билет с уникальным номером и статусом. Одно мероприятие имеет ограниченное количество мест.

## Возможности

- просмотр, добавление и поиск участников;
- создание и просмотр мероприятий;
- поиск и фильтрация мероприятий по числу мест;
- регистрация участника на мероприятие (создание билета);
- отмена билета и изменение его статуса;
- проверка доступности регистрации;
- сохранение данных в JSON-файлах.

## Основные сущности

### Participant — участник

Атрибуты:
- `id` — идентификатор;
- `name` — имя;
- `email` — email.

Методы:
- `__str__()` — строковое представление;
- `from_data()` — создать объект из словаря;
- `to_data()` — преобразовать в словарь для JSON.

### Event — мероприятие

Атрибуты:
- `id` — идентификатор;
- `title` — название;
- `date` — дата;
- `max_seats` — максимум мест;
- `registered` — сколько уже зарегистрировано.

Методы:
- `has_free_seats()` — есть ли свободные места;
- `is_suitable_for(min_seats)` — вмещает ли мероприятие N человек;
- `__str__()`, `from_data()`, `to_data()`.

### Ticket — билет

Атрибуты:
- `id` — идентификатор;
- `event` — объект `Event`;
- `participant` — объект `Participant`;
- `status` — статус (`забронирован`, `оплачен`, `отменён`);
- `number` — номер билета.

Методы:
- `cancel()` — отменить билет;
- `change_status(new_status)` — изменить статус;
- `__str__()`, `from_data()`, `to_data()`.

## Взаимодействие объектов

Объект `Ticket` связывает `Event` и `Participant`. В JSON хранятся только
идентификаторы (`event_id`, `participant_id`), а при загрузке в `storage.py`
связи восстанавливаются: `ticket.event`, `ticket.participant`.

Отменённый билет не удаляется из коллекции — меняется только его статус.
Поэтому отменённый билет не блокирует повторную регистрацию.

## Основные операции

- добавление и поиск участников;
- создание, поиск и фильтрация мероприятий по числу мест;
- регистрация участника на мероприятие (создание билета);
- отмена билета и изменение его статуса;
- проверка доступности регистрации;
- сохранение и загрузка данных в JSON.

## Хранение данных

Данные приложения хранятся в JSON-файлах:

- `data/participants.json` — `id`, `name`, `email`;
- `data/events.json` — `id`, `title`, `date`, `max_seats`, `registered`;
- `data/tickets.json` — `id`, `event_id`, `participant_id`, `status`, `number`.

В `tickets.json` хранятся идентификаторы связанных объектов. При загрузке
связи восстанавливаются: `ticket.event` → `Event`, `ticket.participant` → `Participant`.

## Назначение модулей

- `main.py` — точка запуска, меню, пользовательские сценарии;
- `storage.py` — загрузка и сохранение JSON;
- `utils.py` — безопасный ввод (`input_int`, `input_date`, `input_non_empty`, `input_email`);
- `models/participants.py` — класс `Participant` и функции работы с участниками;
- `models/events.py` — класс `Event` и функции работы с мероприятиями;
- `models/tickets.py` — класс `Ticket` и функции работы с билетами.

## Структура проекта

- `main.py` — точка запуска, меню;
- `storage.py` — загрузка/сохранение JSON;
- `utils.py` — вспомогательные функции ввода;
- `models/` — пакет моделей:
  - `__init__.py`;
  - `participants.py` — класс `Participant` и функции;
  - `events.py` — класс `Event` и функции;
  - `tickets.py` — класс `Ticket` и функции;
- `data/` — JSON-файлы;
- `tests/` — автоматизированные тесты.
