# Сервис регистрации участников конференции

## Назначение

Сервис регистрации участников конференции — консольное приложение для управления
участниками, мероприятиями и билетами.

Приложение позволяет:

* просматривать участников;
* добавлять участников;
* искать участников по имени;
* просматривать мероприятия;
* создавать мероприятия с указанием даты и количества мест;
* искать мероприятия по названию;
* фильтровать мероприятия по числу мест;
* регистрировать участника на мероприятие (создавать билет);
* отменять билет;
* изменять статус билета;
* просматривать список билетов;
* проверять доступность регистрации;
* хранить данные между запусками приложения.

## Целевая аудитория

Организаторы конференций и мероприятий, а также администраторы,
управляющие списками участников и регистраций.

## Предметная область

Основными объектами предметной области являются:

* участник;
* мероприятие;
* билет.

Участник может зарегистрироваться на одно или несколько мероприятий
и получить билет с уникальным номером и статусом. Мероприятие имеет
ограниченное количество мест. Один участник не может иметь два активных
билета на одно и то же мероприятие. Отменённый билет не блокирует
повторную регистрацию.

## Основные сущности

### Participant — участник

Объект `Participant` представляет участника конференции.

Основные атрибуты:

* `id` — уникальный идентификатор участника;
* `name` — имя участника;
* `email` — адрес электронной почты.

Основные методы:

* `__str__()` — строковое представление участника;
* `from_data()` — создание объекта `Participant` из набора данных;
* `to_data()` — преобразование объекта в словарь для JSON.

### Event — мероприятие

Объект `Event` представляет мероприятие, доступное для регистрации.

Основные атрибуты:

* `id` — уникальный идентификатор мероприятия;
* `title` — название мероприятия;
* `date` — дата проведения;
* `max_seats` — максимальное количество мест;
* `registered` — количество зарегистрированных участников.

Основные методы:

* `has_free_seats()` — проверка наличия свободных мест;
* `is_suitable_for()` — проверка, вмещает ли мероприятие заданное число человек;
* `__str__()` — строковое представление мероприятия;
* `from_data()` — создание объекта `Event` из набора данных;
* `to_data()` — преобразование объекта в словарь для JSON.

### Ticket — билет

Объект `Ticket` представляет регистрацию участника на мероприятие.

Основные атрибуты:

* `id` — уникальный идентификатор билета;
* `event` — объект `Event`;
* `participant` — объект `Participant`;
* `status` — статус билета (`забронирован`, `оплачен`, `отменён`);
* `number` — номер билета.

Основные методы:

* `cancel()` — отмена билета;
* `change_status()` — изменение статуса билета;
* `__str__()` — строковое представление билета;
* `from_data()` — создание объекта `Ticket` из набора данных;
* `to_data()` — преобразование объекта в словарь для JSON.

## Основные операции

### Работа с участниками

* добавление участника;
* поиск участника по имени;
* поиск участника по email;
* сортировка участников по имени;
* просмотр списка участников.

### Работа с мероприятиями

* создание мероприятия;
* поиск мероприятия по названию;
* фильтрация мероприятий по числу мест;
* сортировка мероприятий по дате;
* просмотр списка мероприятий.

### Работа с билетами

* регистрация участника на мероприятие (создание билета);
* проверка доступности регистрации;
* отмена билета;
* изменение статуса билета;
* просмотр списка билетов.

При создании билета проверяется наличие свободных мест и отсутствие
другого активного билета этого же участника на это же мероприятие.

## Хранение данных

Данные приложения хранятся в JSON-файлах:

* `data/participants.json`;
* `data/events.json`;
* `data/tickets.json`.

При загрузке данные из JSON преобразуются в объекты `Participant`,
`Event` и `Ticket`.

При сохранении объекты преобразуются в данные JSON.

Для связи билета с мероприятием и участником в `tickets.json` используются
их идентификаторы `event_id` и `participant_id`.

## Назначение модулей
### main.py
Точка входа в приложение.
Отвечает за:
* запуск приложения;
* отображение меню;
* получение данных от пользователя;
* организацию пользовательских сценариев.

### models/participants.py
Содержит класс Participant и функции работы с участниками.

### models/events.py
Содержит класс Event и функции работы с мероприятиями.

### models/tickets.py
Содержит класс Ticket и функции работы с билетами.

### storage.py
Отвечает за загрузку и сохранение данных.
Выполняет преобразование:
* JSON → объекты Python;
* объекты Python → JSON.

### utils.py
Содержит вспомогательные функции:

* input_int() — безопасный ввод целого числа;
* input_date() — безопасный ввод даты;
* input_non_empty() — безопасный ввод непустой строки;
* input_email() — безопасный ввод email.

### tests/
Содержит автоматизированные тесты проекта.

## Запуск приложения
Для запуска приложения выполнить:

```text
python main.py
```
После запуска отображается главное меню.

## Тестирование
Для запуска автоматизированных тестов выполнить:
```text
pytest -v
```
Тесты проверяют:
* создание и работу объектов Participant, Event и Ticket;
* методы классов;
* операции с участниками;
* операции с мероприятиями;
* создание и отмену билетов;
* связь билета с мероприятием и участником;
* правило доступности регистрации.
